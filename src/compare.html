Runtime breakdown

Average runtime is total memory preparation + retrieval + answering time divided by recorded questions. Judging and review pauses are excluded. Preparation and combined run totals include recorded rebuilds. Shared preparation is allocated across conversation questions before filtering by question type.

How metrics are computed

Missing answer or judge token totals are filled from prompt + completion tokens when both are available. Derived comparisons are stored in the JSON’s comparison object. Accuracy uses saved binary correctness labels; importing never calls a model or guesses labels.

Tokens per question = (total memory tokens + total answering tokens) / recorded questions. Average runtime = (total memory preparation + retrieval + answering time) / recorded questions. Both exclude judging and include recorded rebuilds and retries. Memory preparation covers module setup, writes, embeddings, summaries, fact extraction, and flushes when recorded. Older reports use their recorded ingestion time without estimating missing setup time. Shared conversation costs are allocated before question-type filtering. Each ingestion ID counts once; records without IDs count separately. Missing required totals stay unavailable. Preparation without questions still enters the overall total.

The lifecycle table separately includes judging and benchmark overhead. Lifecycle totals cover all question types even when filtering. Legacy reports may omit failed attempts. Retrieval p50/p95 in exported comparisons includes packing and any model loading.

Storage sums final stored UTF-8 text across conversations, excluding embedding arrays and runtime overhead. Storage remains a run-level measurement when filtering question types. No memory snapshot means storage is unavailable.
